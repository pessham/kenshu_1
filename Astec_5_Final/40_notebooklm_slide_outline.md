# NotebookLM用 スライド構成詳細アウトライン
## AI活用研修 第5回（最終回）：「現場AI構築発表会 〜あなたの秘伝書を現場に繋げ〜」

このドキュメントは、NotebookLM等のAIに読み込ませてプレゼンテーションスライドを生成するための**詳細な構成プロンプト**です。

---

## 【デザイン指定・全体方針】

- **トーン**: 「卒業式」と「実践の場への送り出し」を両立。達成感と緊張感（現場に出る）が共存するトーン。
- **カラーパレット**: ダークネイビー（#1a2a4a）をベースに、ゴールド（#d4a843）をアクセントカラーとして使用。「秘伝書」「虎の巻」のイメージ。
- **フォント**: 見出しは太めのゴシック体。本文は読みやすいサンセリフ系。
- **アイコン・ビジュアル**: 書物・炎・鍵・ルーペ・コードブロックなどのアイコンを活用。写実的な写真ではなくフラットイラスト/アイコン中心。
- **スライド数**: 全16枚
- **各スライドの構成要素**: タイトル / 本文（箇条書きまたはビジュアル） / 左下に小さくスライド番号

### Slide 11: 失敗学「これをやると死ぬ罠」
- **レイアウト**: 左右2カラム、各カラムに「罠のパターン」
- **タイトル**: AIが「一般論」を答えてしまうとき
- **注釈（小文字）**: ※以下の例は研修用サンプルです。考え方のパターンが現場で活きます。
- **左カラム（罠①）**:
    - アイコン: ⚠️ データベースのテーブル
    - タイトル: 名前と実態がズレているカラム・変数
    - 例: `DEL_FLG` → 「削除フラグ」に見えるが実は「配送済みフラグ」
    - AIの誤答: 「`DEL_FLG = 1` のデータを削除しても問題ありません」
    - 真実: AIは御社の例外を知らない。秘伝のタレに書かなければ永遠に知らない。
- **右カラム（罠②）**:
    - アイコン: ⚠️ サーバー
    - タイトル: 「一般論」が現場では大事故になるケース
    - 例: 502エラー → 「再起動が一般的な対処法」とAIは答える
    - 真実: 特定構成のサーバーでは再起動が壊滅的な事態を招くことがある
    - 教訓: AIの「一般論」と現場の「特例」は別物
- **下部帯（ゴールド背景）**: 社内の「特例」を教えてあげることが、秘伝のタレの本質

---

### Slide 12: AIを選ぶ技術
- **レイアウト**: 判断フローチャート（縦型）+ 右サイドに補足
- **タイトル**: どのAIを使うか？ 3秒で決める判断軸
- **フローチャート**:
    - 「データに社外秘・個人情報・ソースコードが含まれる？」
        - YES → **ローカルLLM一択**（Llama 3.1 + LM Studio）
        - NO ↓
    - 「精度が最優先か？」
        - YES → **クラウドLLM**（GPT-4 / Claude等）
        - NO → **ローカルLLMで十分**
- **右サイドボックス（ゴールドの枠）**:
    - タイトル: 今回カバーしていない第4の選択肢
    - 内容: **IDE連携型AI**（Claude Code / Cursor等）
    - 特徴: エディタに直接組み込まれ、コードベース全体を把握しながら支援
    - 向いている用途: コード解析・仕様書生成・リファクタリング支援
    - 一言: ご自身で調べるか、別の機会に扱いましょう

## 【NotebookLM向け追記メモ】

- スライド10（全体マップ）は矢印フローで視覚的に表現し、第5回（今日）をゴールドでハイライトすること
- スライド11（失敗学）は左右対称の2カラムにして、「罠の例」と「真実」の対比を明確に見せること
- スライド12（AI選び方）はフローチャートを中心に据え、右サイドの「IDE連携型AI」は補足扱いとして控えめなデザインにすること
- スライド15（締め）はテキストを最小限にし、引用文を大きく・余白を広くとった「沈黙」を感じさせるレイアウトにすること
