# 第1回 補足資料：プロンプトとコンテクスト詳解

## 1. プロンプトとコンテクストの違い

### AIにおける言語化の概念

#### なぜAIは期待通りに動かないのか？（人間との"ズレ"の正体）

AIは人間のように「察する」ことができません。人間同士のコミュニケーションでは、共通の文化や経験、暗黙の了解によって言葉を省略しても通じることがありますが、AIにはそれができません。

#### AIにとっての「言語化」の重要性（AIは「察する」ことができない）

AIに正確な結果を得るためには、曖昧さを排除し、明確に言語化する必要があります。「いい感じに」「適当に」といった指示では、AIは何をすればよいのか判断できません。

### プロンプトとコンテクストの違い

- **プロンプト** ＝ 関数名（`function doTask()`）、AIに対する「**命令（コマンド）**」そのもの。

- **コンテクスト** ＝ 引数（`doTask(data, options)`）、命令を実行するために必要な「**前提条件・背景情報（データ）**」。

### プロンプトとは

#### プロンプトとは何か？（AIを動かす「命令文」）

プロンプトは、AIに対して「何をしてほしいか」を伝える指示文です。明確で具体的なプロンプトほど、AIは期待通りの結果を返します。

#### AIが迷わない、明確で具体的な「指示」の出し方

- 動詞を明確にする（例：「生成して」「修正して」「比較して」「要約して」）
- 一つの指示に一つのタスクを含める
- 期待する出力形式を明示する

### プロンプトを考える上で意識しておくべきこと

#### 「タスクの明確化」技術

AIに「何をしてほしいか」を動詞で明確に指示する。

**例：**
- 「生成して」
- 「修正して」
- 「比較して」
- 「要約して」

#### 「役割（ペルソナ）設定」

AIの専門性を定義する。

**例：**
- 「あなたはC#に精通したシニアアーキテクトです」
- 「あなたは経験豊富なUXデザイナーです」

#### 「制約条件」の指定

AIの"暴走"を防ぎ、出力をコントロールする。

**例：**
- 「実行速度を最優先して」
- 「.NET 8の機能を使って」
- 「JSON形式で出力して」
- 「500文字以内で」

#### 「思考プロセス」の誘導（ステップ・バイ・ステップ）

複雑なタスクは分解させ、順序立てて考えさせる。

**例：**
```
以下の手順で実装してください：
1. まず要件を整理する
2. 必要なクラスを設計する
3. 実装コードを書く
4. テストケースを作成する
```

## 2. コンテクストをどのように与えるか

### コンテクストとは何か？

コンテクストとは、AIの精度を高める「背景・文脈」情報です。適切なコンテクストを与えることで、AIはより的確な回答や提案ができるようになります。

### 「何を」コンテクストとして与えるか？（情報の取捨選択）

#### コード
関連する関数やクラス定義（関係ないコードはノイズになる）

#### エラー情報
スタックトレース、コンソールログ

#### 環境情報
プログラミング言語、フレームワーク、ライブラリのバージョン

#### 設計情報
- データベースのスキーマ（DDL）
- API仕様書（OpenAPI）
- ファイルツリー構造

#### 目的・背景
「なぜ」それが必要なのか

**例：**
- 「XSS脆弱性を修正するため」
- 「パフォーマンスを改善するため」

### 「どう」コンテクストを与えるか？（効果的な提示方法）

#### 構造化
マークダウン（特にコードブロック）を使い、情報（コード、エラー、指示）を明確に分離する。

**例：**
````markdown
## 現在のコード
```csharp
public void ProcessData() {
    // コード
}
```

## エラーメッセージ
```
NullReferenceException at line 42
```

## 期待する動作
データが空の場合でもエラーにならないようにしたい
````

#### 順序
重要な情報（前提条件、役割）を先に提示する。

#### 参照（@ / # ）
（CopilotなどのIDEツールの場合）`@workspace` や `#file` を使い、AIが参照すべき範囲を明示的に指定する。

### 「どうやって」コンテクストを与えるか？

#### レベル1：プロンプトによるコンテクト
- 会話の「実行時」に、ユーザーが「毎回」手動で与える
- 同じチャットの中であれば会話履歴をコンテクストとして扱える

#### レベル2：設定によるコンテクスト
- GPTsやGemini（カスタム指示）で与える
- 前提コンテクストは「AIが学習している情報全体」だがその中でコンテクストを設定している状態

#### レベル3：外部連携によるコンテクスト（RAG / ツール）

**①RAG（検索拡張生成）**
- 別ファイルに保存したコンテクストを検索する
- まだAIが学習していない情報も含めて回答する

**②外部ツール**
- AIが「自分では答えられない」と判断したとき、外部の道具（API）を使う
- 例：天気予報APIを参照する

#### レベル4：学習によるコンテクスト（ファインチューニング）
- コンテクストをAIの「脳（モデルの重み）」そのものに焼き付ける
- 特定の分野の専門知識や、特定の話し方を大量に追加学習させる
- AIの「地力」を上げるイメージ

### アンチパターン（失敗例）

#### ❌ 関係ないコードを大量に貼り付ける
コンテクスト汚染により、AIが本質的な問題を見失う

#### ❌ 具体的なエラーログを省略する
「うまく動かない」だけでは、AIは原因を特定できない

### どんなコンテクストが関係あってどんなコンテクストが関係ないのか

#### タスクの目的との関連性

**✅ 有効なコンテクスト**
- ⭕ 過去のやり取り履歴
- ⭕ ユーザーや会社のプロフィール
- ⭕ 良し悪しの評価・判定軸
- ⭕ 時間と場所
- ⭕ 視覚的な情報
- ⭕ タスク固有のテーマやトピック
- ⭕ 制約条件
- ⭕ 対象者（プロンプトに入れるほうがいい場合も）
- ⭕ 環境と時刻（最新情報が絡む場合）
- ⭕ 成功例と失敗例（サンプル）

**❌ 避けるべきコンテクスト**
- ❌ 冗長な詳細
- ❌ 古い数値や過去のままの情報
- ❌ 誤解を招く情報、省略や曖昧な表現
- ❌ 推測に基づく情報や人によって解釈が分かれる情報
- ❌ データのバイアス、偏り
- ❌ 無関係な事実
- ❌ 個人的な感情
- ❌ 機微情報（個人情報、秘密情報）でタスクに不要なもの

## 3. コンテキストウィンドウとは？

### コンテキストウィンドウとは何か？

**モデルが一度の入力処理で"認識可能な最大トークン数"**

AIには一度に処理できる情報量（トークン数）に制限があります。この制限を「コンテキストウィンドウ」と呼びます。

### なぜウィンドウ制限が重要なのか？

- ウィンドウを超えた情報は無視される、または古い情報が削除される
- 長い会話では、最初の方の文脈が失われる可能性がある
- 大規模なコードベースを一度に処理できない場合がある

### ウィンドウを超える情報を投入するとどうなるか？

- 古い情報から順に削除される（FIFO方式）
- エラーが発生する場合もある
- 回答の品質が低下する

## 4. コンテキスト制御のポイントは？

### 情報の要約
履歴をそのまま詰め込まず、要点だけを抽出する

### 優先順位の明示
「何が重要で、何が補足か」をプロンプト設計で示す

### 外部メモリとの併用
RAG（検索補助）などを使って、必要なときだけ情報を呼び出す

### 情報の分割
1つのプロンプトに全部渡さず、段階的に渡す（チャンク処理）

### 会話履歴の圧縮
過去の応答を自動で要約し、少ないトークンで文脈を保つ

## コラム：おすすめAIツールの紹介

### 1. 対話型AI（すべての基本となる「頭脳」）

#### Gemini (Google)

**特徴:** Googleのサービスと連携が最強。

**スライド生成:** Googleスライドと連携し、指示だけでスライドの下書きや画像生成が可能。

**コード・自動化:** 最新モデル（Gemini 3 Proなど）は非常に長いコードやドキュメントを一度に読み込めるため、大規模なリファクタリングが得意。

#### ChatGPT (OpenAI)

**特徴:** 最も汎用的で、迷ったらこれを使う標準ツール。

**コード補完:** 「Canvas」機能を使うと、コードの特定部分をピンポイントで修正・リファクタリングしやすい。

**自動化:** 「Advanced Data Analysis」で、Excelデータの集計やグラフ作成、PPTファイルの生成まで自動化できる。

#### Claude (Anthropic)

**特徴:** 「人間らしく自然な文章」と「論理的なコード生成」が得意。

**リファクタリング:** コードの意図を読み取る能力が高く、バグ修正や複雑なロジックの整理（リファクタリング）で非常に優秀な提案をする。

**自動化:** 「Artifacts」機能により、チャット内で即座にアプリのプレビューや図解を表示できる。

---

### 2. コーディング特化（開発を爆速にするツール）

#### Antigravity (Google)

**特徴:** **【最新注目】** Googleが発表した新しい「特化型AIネイティブなコードエディタ（IDE）」。

**コード補完・自動化:** 単にコードを書くだけでなく、エージェントが「計画（Plan）」を立ててから実装し、ブラウザでの動作確認まで自律的に行う。

**位置づけ:** VS Codeをベースにしており、Cursor（人気のAIエディタ）の強力なライバル。

#### Claude Code (Anthropic)

**特徴:** ターミナル（黒い画面）の中で動く、エンジニア向けのAIアシスタント。VS Codeの拡張機能としても使用可能。

**自動化:** コマンドラインで「このプロジェクトのテストを実行して、エラーを直して」と頼むと、ファイルを分析して修正案を出し、実行まで行う。

**リファクタリング:** プロジェクト全体を理解した上での大規模な修正が得意。

#### Codex (OpenAI)

**特徴:** ほぼClaude Codeと遜色なく使えるレベルにまでレベルアップ。VS Codeの拡張機能としても使用可能。

**Claude Codeとの比較:** Codexの方が単一ファイルの編集に強みがある、Claude Codeはプロジェクト全体の理解とマルチファイル編集で優位性といった評価もあるが、まあどっちもぶっちゃけそんなに変わらない。

#### Devin (Cognition AI)

**特徴:** これまでのAIが「人間のサポート（副操縦士）」だったのに対し、Devinは**「人間と同じようにタスクをこなす同僚（エンジニア）」**という立ち位置です。

**自動化（ここが最強）**

- **環境構築からデプロイまで全自動:** 初級者が最もつまずきやすい「開発環境の構築」や「ライブラリのインストール」を、Devinは自分専用の仮想PC（ターミナル、ブラウザ、エディタ完備）で勝手に行います。

- **自己修正ループ:** コードを書いてエラーが出たら、自分でエラーログを読み、原因を検索し、コードを修正して再度実行します。「書いて終わり」ではなく「動くまでやる」のが最大の特徴です。

**コード補完・生成**

- **「補完」ではなく「実装」:** 「この関数の続きを書いて」ではなく、「このウェブサイトのクローンを作って」「Upwork（仕事依頼サイト）にあるこの案件をやって」というレベルの指示で、プロジェクト全体を構築します。

- **計画立案:** いきなりコードを書くのではなく、「まずはAをして、次にBをする」という計画（Step-by-step）を画面上に表示し、進捗を人間に報告しながら進めます。

**リファクタリング・デバッグ**

- **Printデバッグも自分でやる:** 複雑なバグがある場合、Devinは自分でprint文などを仕込んで動作確認を行い、問題箇所を特定して修正します。

- **レガシーコードへの対応:** 知らない言語や古いコードでも、自分でドキュメント（APIリファレンスなど）をブラウザで検索して読み込み、学習しながら修正を行います。
